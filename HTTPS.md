# Подключение HTTPS для ea.csweekly.ru

Подготовлены `compose.https.yaml` и `Caddyfile`. Caddy работает перед существующим Nginx, получает и продлевает публичный сертификат автоматически и переводит HTTP на HTTPS. Адрес постера при сборке меняется на `https://ea.csweekly.ru/images/poster.png`.

Эти команды выполняются **на сервере 31.57.93.209, в папке проекта**. Конфигурация подготовлена локально; на удалённом сервере она ещё не запущена.

## 1. DNS и порты

В DNS должна быть запись:

```text
Тип: A
Имя: ea (в зоне csweekly.ru)
Значение: 31.57.93.209
```

При проверке 14 октября 2026 Google Public DNS уже возвращал этот IP. Если у домена есть AAAA-запись, она тоже должна вести на этот сервер; ошибочная IPv6-запись может мешать проверке сертификата.

Открой входящие TCP-порты **80 и 443** в панели хостинга/фаерволе. UDP 443 используется для HTTP/3, но для работы HTTPS не обязателен. Если на сервере уже используется UFW:

```sh
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
```

Серверу также нужен исходящий доступ к центру сертификации. На портах 80/443 не должно быть второго Nginx, Apache или другого контейнера. Если там работают другие сайты, используй общий существующий прокси вместо запуска второго Caddy.

## 2. Обновить файлы на сервере

Скопируй обновлённый проект, включая `compose.https.yaml` и `Caddyfile`, своим обычным способом. В репозитории можно получить изменения через `git pull`, если они уже закоммичены и отправлены.

В `.env` можно добавить настройки (без схемы и слеша в SITE_DOMAIN):

```dotenv
SITE_DOMAIN=ea.csweekly.ru
SERVER_IP=31.57.93.209
```

Они необязательны: эти значения уже используются по умолчанию. HTTPS-конфигурация сама задаёт `VITE_SITE_URL=https://ea.csweekly.ru` при сборке, даже если для старого HTTP-запуска у тебя оставлен `SITE_URL=http://31.57.93.209`.

## 3. Переключить запуск на HTTPS

Сначала проверь конфигурацию:

```sh
docker compose -f compose.https.yaml config --quiet
```

Собери приложение и скачай Caddy, пока старый HTTP-сайт продолжает работать:

```sh
docker compose -f compose.https.yaml build invitation
docker compose -f compose.https.yaml pull caddy
```

Теперь останови текущий контейнер этого проекта, чтобы освободить порт 80, и запусти HTTPS-версию. Между командами сайт кратковременно недоступен:

```sh
docker compose down
docker compose -f compose.https.yaml up -d
```

Выполняй команды из той же папки проекта. Если исходный запуск использовал `-p`, используй то же имя проекта во всех командах.

**Не объединяй** `compose.yaml` и `compose.https.yaml` через два `-f`: HTTPS-файл самостоятельный, иначе может сохраниться старое назначение порта 80 для Nginx и возникнуть конфликт с Caddy.

Посмотри состояние и журнал сертификата:

```sh
docker compose -f compose.https.yaml ps
docker compose -f compose.https.yaml logs --tail=100 caddy
```

При первом запуске дождись получения сертификата. В случае ошибки журнал покажет, что именно не получилось: DNS, проверка домена, занятые порты или соединение с центром сертификации.

## 4. Проверка

```sh
curl -I https://ea.csweekly.ru/
curl -I https://ea.csweekly.ru/images/poster.png
curl -I http://31.57.93.209/
```

Ожидается: сайт и постер возвращают `200 OK`; старая HTTP-ссылка по IP — `308` с `Location: https://ea.csweekly.ru/`. В браузере открывай **https://ea.csweekly.ru/**. Сертификат предназначен для домена; открытие `https://31.57.93.209/` этой конфигурацией не поддерживается.

Проверить адрес изображения в метаданных:

```sh
curl -sS https://ea.csweekly.ru/ | grep 'og:image'
```

Должен быть адрес `https://ea.csweekly.ru/images/poster.png`.

## 5. Превью в Telegram

Проверь новую доменную ссылку в обычном чате Telegram:

```text
https://ea.csweekly.ru/?preview=https-v1
```

Это новый URL для проверки превью. Обновление HTTPS не гарантирует, что Telegram немедленно покажет карточку; на сервере можно проверить, запросил ли её робот:

```sh
docker compose -f compose.https.yaml logs --since=10m caddy
```

Caddy пишет журнал запросов, включая путь, статус ответа и User-Agent. Ищи запросы с `TelegramBot` к странице и `/images/poster.png`. Если запросов нет, робот ещё не обращался к серверу. Если есть ошибки или запрос только к странице, журнал поможет продолжить диагностику. При `200` для обоих запросов сервер успешно отдал метаданные и изображение.

## Обновление и откат

Все следующие обновления запускай с HTTPS-файлом:

```sh
docker compose -f compose.https.yaml up --build -d
```

Сертификаты хранятся в `caddy_data`. При обычной остановке том сохраняется; не удаляй его через `down -v`, чтобы не терять состояние сертификатов.

Если необходимо вернуться на прежний HTTP-запуск:

```sh
docker compose -f compose.https.yaml down
docker compose up --build -d
```
